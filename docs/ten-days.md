# 十日谈 · Aegis 开发历程

> D9、D10 写于提交当天（2026-09-28）。

## 为什么想做这个

OpenAI 攻击 Hugging Face 这件事，把智能体网络攻击摆上了台面；网络安全问题正变得越来越复杂。我所在的企业，因为行业特殊性，对信息系统安全看得特别重。

因此，我们每年都会做一次授权红蓝对抗演练。流程不复杂：红队扮成攻击者，在事先划定的授权范围内找漏洞、试攻击路径；蓝队负责防守，看监控、做响应、确认问题并修复；修完再由红队复测，确认同一条攻击路径真的打不通。一次演练基本就是“授权—攻击—防守—修复—复测”这几步，一个漏洞从发现到闭环，常常要以周计。

但一年只有一次窗口，过了就得等来年；今年红队踩出来的攻击路径，明年换个人，还得从头再走一遍。

我们想知道，这套流程能不能交给智能体天天跑：红方在授权环境里找漏洞，授权范围和人工演练一样写在配置里，一点不放宽；蓝方调模型生成补丁，先过门禁再部署；再训一个小模型专门看流量当裁判。更进一步的想法是，每一轮对抗留下的东西都别浪费：打得通的攻击沉淀成经验库，真实的请求响应变成裁判的训练材料。等到下一次演练开场，系统已经不是上一年的它了。

一台 DGX Spark 装得下这套东西：125B 的模型负责生成补丁，4B 的小模型负责判流量，智能体流程在中间跑。题就这么定了。项目叫 Aegis，中文叫神盾。

## D1 · 杀进程之前，先想想自己是不是也在名单里

第一天几乎都在搭底座、摸模型脾气。

Qwen3.8-Flash-Next 125B NVFP4 跑上 SGLang 之后，我们做了三个实验。关掉思考模式，一次生成从 17.4 秒降到 1.3 秒，快了 13 倍；并发开满，吞吐纹丝不动，一直停在每秒 23 个 token 左右，说明在这台机器上排队就好，别指望并行；StepFun 云端直连 0.57 秒，留给后面做补丁复核用。当晚把黑板状态机、scope 校验、payload policy 三件治理骨架提交入库。中间还发现 SGLang 不认 `developer` 角色，写了个兼容层放进仓库。

这天最深的教训来自一个很蠢的事故。我想停掉一个下载脚本，用了 `pkill -f download`，这个匹配模式把自己的 shell 也扫了进去，进程自杀，会话当场断线。同一个坑后来又咬了我们三次：deploy.sh、抓包代理、批量脚本。最后定下两条规矩：停服务先用 `ss -tlnp` 按端口找到 PID 再动手；发给远端的命令一律用单引号包起来。

## D2 · 自以为写好的武器库，一半是哑的

要测红方，得有个靶子。现成的漏洞靶场和真实业务差得太远，我们干脆自己写了个带漏洞的业务小站 edu-lite，起了 A、B 两个实例，参数名完全不同，防止探测逻辑过拟合到一套参数上。功能测试两边都是 7/7。良性流量发生器也在这天好了，给裁判产出了第一批标签。

真正翻车的是武器库本身。验收 harness 第一次跑，12 个 payload 只中了 7 个：upload 那一组全漏了 Cookie 头；sqli 的报错注入在 SQLite 上根本行不通，它解析太宽容，压根不报错。本以为写好的东西，一半是哑的。从这天起，held-out 验收成了硬关卡，新武器必须打真靶验过才算数。

## D3 · 一个不可能失败的证明，什么都没证明

第三天第一次跑通完整闭环：红方在 A、B 两个实例上都找到了漏洞，蓝方生成补丁，部署，重放攻击，各花 4.3 秒，状态 CONVERGED。

我兴冲冲宣布 re-attack 清零，独立评审agent 当场推翻。问题出在一个谁都没想到的地方：打补丁要重新部署，重新部署会清空 SQLite 会话，而 re-attack 复用的就是旧会话，当然清一色 401。也就是说，这个收敛证明在数学上不可能失败，所以它什么都没证明。修复分两步：重放之前强制重新登录；再加三个回归单测把这个口子焊死。“每个数字都能当场点验”，这条底线就是这天立下的。

这天还记下两个隐蔽的坑。一个是 opcache 时间窗：打完补丁 2 秒内去做验证，跑的还是旧代码的缓存，验证结果会骗人。另一个是回显假 marker：`VMARK9PASS` 这串字符被页面原样输出回来，漏洞看着怎么都打不死，后来把判定逻辑改成看数据侧的特征才解决。

## D4 · 失败路径走得干净，也算收获

第四天把漏洞类别做成了插件。upload_bypass 和 rce_deser 两个新类别接进来，管线一行没改，三个类别依次闭环。

LLM 补丁第一次实跑出了个乌龙：生成的代码被我们自己的 php -l 检查拦下，`<?php` 头重复了。查下来是 prompt 里多包了一层。不过这次失败走得干干净净，拒绝、恢复现场，一步没乱，这个反面例子成了当天最好的素材。

这轮实弹还量出一个关键数字：LLM 适配层闭环要 57 秒，模板路径只要 2.8 秒，20 倍的差距。后来路由就按这个来，大部分情况走模板，值得的时候才请模型。

## D5 · 机器骗过自己的两种方式

第五天八个类别全部闭环，也撞上了两个“机器骗过自己”的案例。

第一个：xss 补丁明明生效了，verify 还有 3 条命中。查下来是 `VULNXSS_A1()` 这段文本经过 htmlspecialchars 转义后原样活着，marker 选错了判定面。“转义后必然消失的结构”和“看起来独特的文本”是两回事，该盯着前者。

第二个更冤：brute 攻击组打 admin，补丁生效前的 6 次失败把 admin 账号锁死了，后面的会话全部跟着遭殃，测试自己把自己的靶子打哑了。修法是换一个“牺牲性用户名”，专门拿来挨打。

这天还把 P0 级补丁的三重审查门禁写进了管线：diff 边界、后门模式、异构复核，fail-closed，配了 5 个单测。soak 测试跑起来，1653 轮零失败。

## D6 · fail-closed 拿可用性换安全

第六天红蓝开始共演化。marathon 多轮收敛引擎 8 类 × 2 轮跑 10.3 秒，第 2 轮全部类别零命中。Console 参照 Rivet 重构成三栏工作台。judge 训练线也通了，数据按家族切分，防止训练集和考试集是一家人。

lfi 类这天被打了回来，理由是“异构复核 API 瞬时故障”：fail-closed 把一次网络抖动当成了危险信号。这是设计出来的行为，不是 bug，但代价也明摆着，它拿可用性换安全，阈值怎么定，得老老实实想清楚，不能两头都要。

还有一桩悬案告破：rce_deser 偶尔整段空写，查了很久，最小复现最后证明不是内容审查，是全文件长输出这个模式本身会失败。另外评审agent 发现 judge 级 1 那套开卷 100% 的结果不可信，证据存档，当了反面教材。

## D7 · 零失败不等于测过

第七天冻结，所有数字只对测试负责。

评审agent 翻 soak 日志的时候发现，“1653 轮零失败”那一栏，内存是空的。零失败不等于测过内存，我们差点把一个没测过的维度当成通过项报出去。同一天，一份移交说明里有一条没核实过的声明也被评审agent 抓住。移交出去的说法同样必须能自证，这是从这天立下的规矩。

B 集这天交卷封存：judge 净卷准确率 0.9989（家族聚类 CI[0.9976,0.9998]，n=7266），对比零样本的 0.8431。jail 测试的两档 RoE 落地；重定向出笼那个 P0 用 `_pinned_request` 钉死。级 3 我们主动把口径降了级，只主张改名鲁棒性和未见响应形态，测不到的不说。

## D8 · 数字在图上长得像什么，程序查不出来

第八天做对外材料。deck 初版的柱状图把 0.8431 四舍五入显示成了“1”，一个错误数字差点挂上关键页。这个问题是逐页用眼睛看出来的，程序检查毫无反应。程序验得出数值对不对，验不出它“看起来像什么”。

这天把项目整理成第一次接触也能看懂的样子：JUDGES.md 给出三分钟的导览路径，每个数字都能查到出处；六页 deck，每个数字标了 JSON 来源；golden-run 回放包，没有 Spark 环境也能完整重放整场对抗。

## D9 · 开拍之前先对时钟

第九天拍摄。下午第一次实拍，录到一半发现大屏上挂的是前一天的旧数据，视频里“刚跑完的 run”，时间戳是昨天的，只能全部重录。手册从此多了一条：开拍前先对时钟，页面取数的 `created_at` 和墙钟差超过 2 分钟就重置环境。公网演示链接（Cloudflare 快速隧道）当天还中途掉线重连了一次，地址会变，所以演示入口不能指望随机域名，正式入口以提交包里的文件为准。

4 分钟成片一次录成，主线是 run-20260927-140612-399b：修补前 SQLi marker 命中，三道门禁 3 项 PASS，修补后同一个注入重放 0/2，正常业务断言通过（「图书馆」命中、无效关键字不命中），靶场恢复，run succeeded。一次运行把攻击复测、门禁、部署身份、收据全链都留了下来。九页 RSI deck 同一天定稿，把“受控 RSI”拆成四步讲：红方自己找风险，JEV 独立判流量，蓝方在门禁约束下自修补，结果回流成裁判的训练材料。deck 里也写清了边界：参赛的是已经训练、已经部署的 v3；这轮的新样本要过人工审核才进下一轮训练；下一版判官还没开训。

## D10 · 交卷之前，让别人再挑一遍刺

提交包第一版差点带着问题出门，独立复核连抓三处。第一，打包规则会漏掉手工补进去的证据和结果 JSON，“构建两次、结果一致”从此成了硬要求。第二，训练材料链的标签把“攻击但没打穿”标成了“良性”，早先“107/122 判官误报”的结论跟着作废，错的是我们的标签口径，不能拿它去断言判官读数的对错；116 条旧候选重新标注隔离，旧标签留在 legacy_labels 里存档。第三，README 承诺了包里不存在的运行路径，缺靶站、缺载荷，却写着“可跑完整攻击链”。改的过程中又陆续发现数据保真、标签审批、媒体验收几处问题，一起补上，定成了规则：导出白名单、构建后断言、training_ready 闸门、评审包三条准确入口。

最终包重新构建，交付四分钟视频、九页 deck、44 秒真实技能短片、主 run 16 件证据和逐文件哈希。能力线公开验收 75 项测试和 16 项子测试通过；私有和 GPU 环境的完整验证没有冒称通过，记录在 VALIDATION.json 里。技能调用也补录了一次真实的：run-20260928-155647-3290 由技能 CLI 启动，约 90 秒到终态，返回 verified_restored，17/17 项证据核验通过，5 条候选入队，完整操作留了底，短片只把等待段压成 4 倍速、配了中文旁白。

## 没做完的

下一版判官还没开训，这轮攒下的新样本在排队等人审。红方经验库目前只在同类目标上验证过，换个目标家族效果如何，还没有数据。每天的关键改动和运行证据，仓库里都有 commit 和 run id 可以对上。

十天里，每次翻车最后几乎都落成了一条单测、一道门禁或者一条口径。“像攻击”不等于“是攻击”，“没打穿”也不等于“是良性”；模型读数只用来分析分歧，判定只认 marker、业务断言和复测这些硬信号。这些规矩都不好看，但下一次，同样的错误机器自己就能抓住。
