# 新开发基线：并发完整性与服务保护

开发分支从提交版 submission-20260929-r4 创建，单独位于 aegis-next。
原演示仓、原模型、原现场台账和公开 main 不受本轮改动影响。

## 已实现

- 学习队列和 POC 候选队列的读取、追加、去重、审批、标签修订共用跨进程事务锁。
  唯一临时文件、fsync 和原子替换保护已提交内容；坏行显式报错并保留原文件。
- 标签审核带递增 revision；审核旧标签的准入请求不能批准新标签。
  桥接 CLI 把审批人、备注和对应标签修订放在同一事务内写入。
- 训练材料导出锁定队列快照及输出目录，样本、统计、配对、队列哈希来自同一状态。
- Console 将幂等查询、忙检查、运行预约和派生纳入跨进程创建锁。
  同请求键同参数返回同一运行；参数不同返回 409。历史查找不再局限最近一千轮。
- Console、任务进程和恢复入口共用目标锁，子进程显式继承锁路径。
- JEV 报告将已确认标签的 FP/FN、待审分歧、弃权分开，给出总数及样本引用。
- JEV HTTP 服务限制连接和推理容量，拒绝超大输入，限制读取总时长及排队时间。
  慢速逐字节请求不能无限延长读取期限；推理异常返回结构化错误并释放容量。
  返回排队、预处理、推理和请求总耗时。GPU 判读协议沿用现有共享渲染。
- 补齐公开快照缺失的教学靶场与插件静态资源，来源和哈希记录在 runtime-assets.json。
  MiniLedger 良性流量脚本仅请求明确的本地靶场，禁用代理与重定向。
- 锁定 CPU 依赖，加入 Windows/Ubuntu CI、只读 doctor 和相关回归。
  两个原有 Bash 入口的行尾统一为 LF，避免 Linux 上出现 CRLF 执行错误。

## 验收边界

本轮运行的是 CPU、本地文件/进程、隔离 HTTP 服务和技能桥接测试。
没有对原演示服务发起新攻击，没有加载 GPU 模型，也没有重新训练 JEV。
新增服务在 Spark 与 125B 模型共同常驻下的显存和 p95，需要单独实机验收。
CI 已配置两系统，但本轮本地执行环境是 Windows；不能写成已通过 Linux CI。

公开 claims 校验命令为 python bench/train/assert_claims.py --public。
它明确列出未检验的私有 computed 条目。省略 --public 是完整严格校验，
缺少私有原始语料时仍失败；pytest 的私有数据项明确 skip，不充当通过。

根 VALIDATION.json 与 FINAL-BUILD-MANIFEST.json 是 r4 历史发布记录。
它们不是当前开发源码的成绩单；本轮结果记录在本目录的 regression-final.json。
不重新生成历史记录来掩盖代码已变化这一事实。
