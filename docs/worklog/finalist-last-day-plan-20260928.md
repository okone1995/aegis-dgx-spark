## RSI 要展示三个不同的改进环

### 红方：经验沉淀后，下一轮用上

施工记记录“零样本 21 发 → 人审入库 → 下轮 3 发命中”。这是可以优先补强的短对照：核对两份原始 hunt 结果、同目标/配置、写回 provenance，再显示两个独立轮次和请求数。尚未完成原始对账之前，只作为待核素材，不将施工记中的数字直接抄成新实测。

说明这是同一已知案例上的库复用，不是未知攻击泛化，也不是模型权重自己变强。

### 蓝方：代码改变后，攻击失效且业务通过

主演示展示实际 diff、修补前成功证据、修补后非空攻击重放 0/2、正常业务通过及收据。保留 run ID。演示默认恢复是为了可重复验证，不把 restored 说成生产补丁已长期部署。

### JEV：已训练的能力与下一轮学习分开

展示 v3 的模型身份、离线评估、Spark 单发时延与线上实际判断。离线 B 卷的同形请求边界须保留，不宣称未见攻击泛化。

主演示中规则和 JEV 都识别了攻击；JEV 也将登录流量误判成攻击。因此这条 run 不证明“JEV 补回了规则漏报”。正确讲法：展示独立判断和真实分歧；JEV 不决定修补成功，分歧进入人工复核。规则互补优势应使用版本明确的独立对照实验，不混用 v2b 与 v3。

下一版权重未训练不是赛前必须赶工的项。已训练 v3 + 数据反馈机制 + 明确质量控制，足以构成可解释的原型路线；不要宣称整个模型升级循环已完成。

## 预备五个答辩问题

1. **RSI 在哪里？** 红方经验库已经复用，蓝方补丁经复测验证，JEV v3 已训练部署；新样本的下一版权重升级尚未完成。
2. **怎样避免为了安全把业务关掉？** 同攻击重放与正常业务/功能测试共同验收，网络错误和失去认证不算阻断成功。
3. **为什么需要 JEV？** 小模型提供独立流量分类与分歧发现，实际互补收益用对应版本的对照实验支持；它会误判，因此不作为修补 oracle。
4. **别的 agent 真能用吗？** 四个新技能有执行入口和测试，self-repair 已验登记案例；需要 Aegis 后台和授权配置，其他目标需适配。
5. **为何用 DGX Spark？** 用真实部署证明本地大模型修补与 JEV 判读的承担部分，解释模型精度/量化/服务分工；训练地点和云端复核边界如实说明。
